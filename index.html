Start from what Sarwa already has, then find what's missing

Each concept reuses something Sarwa already runs (named accounts, the Halal range, Invest, Trade and Save balances, dividend reinvesting), so it adds a new front end to existing plumbing instead of a new product.

  2. Check for gaps

  3. Build to the system

    Brand tokens from the site CSS, layouts from the app screenshots, real fees and risk levels, and FSRA-era disclaimers.

Engineering

Built the way I'd build them for production

Each prototype is one self-contained file with no framework and no build step. The choices below carry straight over to a React or React Native codebase.

One state, pure renders

A single state object feeds every screen, and each screen is a pure render of it. In React that maps to a reducer plus memoised selectors, which keeps the maths testable away from the UI.

Maths you can check

The goal planner works out each month's mean and variance in closed form and fits a lognormal for the 10th, 50th and 90th percentiles. It agrees with a 40,000-path Monte Carlo to about 1%. Money is held in integer cents, and the formulas sit in a comment at the top of each script.

Hand-drawn SVG charts

No chart library. Charts scrub with pointer or arrow keys, and an aria-live readout announces the value. Chart ticks and labels come from one scale.

Arabic and right-to-left

Layouts use logical CSS properties, so an EN / ع toggle mirrors the app cleanly. Figures and time-series charts stay left to right, as Arabic finance apps do.

States you can link to

Screens and edge states open from the URL, e.g. ?screen=whatif or ?state=error. Design review and QA can land on a loading, empty, error or no-permission state in one click.

Accessible by default

Tap targets of 44px and up, visible focus rings, labelled sliders, and sheets that close on Escape and give focus back. Motion respects reduced-motion settings.
